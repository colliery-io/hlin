{{- if eq .Values.config.auth.strategy "trusted-header" }}

Identity comes from the {{ .Values.config.auth.trustedHeader.header }} header,
which means the shell believes whatever that header says. Anything able to reach
a pod directly is therefore whoever it claims to be — and in a cluster a pod IP
is reachable from the rest of the namespace by default. An ingress in front is
not on its own enough: restrict what can reach these pods, with a NetworkPolicy
or a mesh.
{{- end }}

breaking change across one goes unnoticed — which is the thing the versioning
exists to catch. Set config.databaseUrlSecret to point at a Postgres.

{{- if not .Values.signingKey.existingSecret }}

The signing key will be generated on first start and kept on a volume. That is
correct for one replica. More than one needs signingKey.existingSecret, so they
share an issuer rather than being several — the chart will refuse the other
combination.
